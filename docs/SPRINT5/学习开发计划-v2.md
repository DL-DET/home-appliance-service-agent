## 0. 一句话定位

不是“给大模型套一个聊天框”，而是“混合式客服 Agent”：

> 高频、强约束的流程走确定性工作流；开放式问题走 ReAct；用离线评测 + 运行轨迹 + 线上反馈驱动迭代。

它要回答三个工程问题：

1. 模型什么时候该查知识库，什么时候该查业务系统？
2. 多用户环境下，如何保证模型不会读到别人的订单和使用记录？
3. 回答错了，如何定位是检索、工具、权限还是生成出了问题？

### Day 0：基线冻结（约 2 小时）

- 统一测试数、评测集条数、P95 口径。
- 把 README 的基线数字改成与 `eval/agent_report*.md` 一致。
- 跑一遍 `pytest`，提交当前未跟踪的评测代码。
- `git tag baseline-v1`，新建 `sprint5/learning-v2` 分支。

验收：`pytest` 全绿；README、优化待办、评测报告三处数字一致；GitHub 能看到最新提交。

### Day 1：评测加固

- 学：LLM-as-judge 的 rubric 怎么写；人工校准怎么做；CI 回归门禁怎么设。
- 做：
  - `eval/judge.py`：faithfulness / answer_relevance / context_precision 三维打分，固定 JSON 输出。
  - `prompts/judge_prompt.txt`：评分标准 + 反例。
  - 人工标 20 条做校准；judge 默认 `qwen-plus`（`qwen-turbo` 实测触发 429，可用 `JUDGE_MODEL_NAME` 覆盖），失败重试 1 次。
  - CI 增加手动/nightly 的 5 条冒烟；无 Key 时用回放夹具。
- 验：judge 与人工一致率 ≥ 80%；人为改坏一处能被 CI 拦下。
- 产出：报告新增 judge 表；一段「为什么关键词评测不够」的面试话。

### Day 2：路由与安全前置

- 学：意图分类、置信度、混合意图回退、可信身份边界。
- 做：
  - `agent/router.py`：知识 / 订单 / 报告 / 安全 / 通用五类路由，订单号提取。
  - 安全前置：跨用户请求在进入工具前拒绝，返回与“不存在”一致的结果。
  - 混合意图回退 ReAct，记录误路由。
- 验：30 条用例路由准确率 ≥ 95%；security 类业务工具调用 = 0；误路由可回退。
- 产出：路由表；一条「为什么路由比提示词可靠」的面试话。

### Day 3：工作流与工具预算

- 学：确定性工作流、状态机、幂等、工具预算与重复调用缓存。
- 做：
  - `agent/workflows.py`：报告、订单、知识三条确定性流水线；通用问题回退 ReAct。
  - `middleware.py`：单请求工具预算、重复调用缓存、超限明确报错。
  - 报告流程不再依赖模型自由选工具。
- 验：4 条报告全部完成，0 次 `GraphRecursionError`；知识 RAG 触发率 100%；单请求工具调用 ≤ 6 次；订单状态由代码返回。
- 产出：P0 关闭的前后对比表。

### Day 4：检索质量

- 学：BM25、RRF、重排、阈值校准、引用校验。
- 做：
  - `rag/hybrid_retriever.py`：BM25 + 向量 + RRF。
  - `rag/citation.py`：代码级提取、校验、补全来源。
  - `rag/vector_store.py`：`--rebuild`、删除旧 chunk、记录索引版本。
  - 同一份评测集跑：baseline / +hybrid / +threshold 三行消融。
- 验：Hit@3 ≥ 0.9；Recall@3、MRR 有记录；引用覆盖率 100%；`battery-safety` 修复。
- 产出：检索消融表；一条「为什么纯向量漏检」的面试话。

### Day 5：记忆与多轮

- 学：上下文工程、滚动摘要、偏好记忆、指代消解。
- 做：
  - `agent/memory.py`：超过 N 轮把旧消息压缩为摘要，保留最近 K 轮原文。
  - 用户偏好长期记忆：只存偏好，不存订单/身份；提供清除入口。
  - 新增 8 条多轮用例：指代消解、上下文切换、记忆召回。
- 验：多轮指代准确率 ≥ 80%；10 轮对话 token 降 ≥ 30%；记忆清除测试通过。
- 产出：记忆表 + 多轮评测；一条「30 轮怎么办」的面试话。

### Day 6：观测、韧性与成本

- 学：trace/span、TTFT、SLO、重试/退避/熔断、降级回答、token/成本。
- 做：
  - `utils/tracing.py`：request_id、每步耗时、工具调用、token/成本。
  - 超时、有限重试、熔断、降级回答；只对幂等读操作重试。
  - 3 条故障注入：模型超时、工具异常、无检索结果。
  - 埋点 TTFT、P50/P95、单次成本。
- 验：失败 60 秒内对用户可见；不会无限重试；一次失败能靠 request_id 串起来；成本表有数字。
- 产出：观测表 + 故障注入证据；一条「失败怎么定位」的面试话。

### Day 7：交付与面试

- 学：打包、演示叙事、STAR。
- 做：
  - `Dockerfile`、`docker-compose.yml`、`.dockerignore`。
  - README 四张表：评测、消融、成本与延迟、失败案例。
  - 2 分钟演示视频；20 问模拟面试；三版简历描述。
- 验：`docker compose up` 一条命令启动（装不上则本地 venv + 录屏）；20 问能脱稿。
- 产出：可投递版本。

## 8. 风险与裁剪线

- **范围**：7 天很紧。超时就按「语义缓存 → 公网 Demo → 多轮记忆 → judge」的顺序砍。
- **评测偏差**：30 条自己标的，有偏；写清标注口径和人工抽检比例。
- **模型波动**：同一批用例跑 2 次取均值，避免误判。
- **API 成本**：全量评测前先估算调用次数，先跑 5 条。
- **Docker**：Windows 11 家庭版可能需要 WSL2；装不上就本地 venv + 录屏，不阻塞交付。
- **记忆隐私**：只存偏好，不存订单/身份，提供清除。
- **缓存串用户**：key 带用户作用域，订单/报告强制绕过，必须有隔离测试。
- **Judge 一致性**：先人工校准，低于 80% 不上线。
