## 2. 五天分阶段

### Day 1：保住退路 + 评测先行（不写业务功能）

**Step 0：保住退路**

```bash
git tag baseline-v1
git switch -c sprint5/eval-first
```

**Step 1：30 条 Agent 评测集**

`eval/agent_cases.jsonl` 字段：

```json
{
  "id": "knowledge-battery-safety",
  "query": "机器人电池鼓包还能继续用吗？",
  "category": "knowledge",
  "expected_route": "knowledge",
  "expected_capability": "rag",
  "expected_tools": ["rag_summarize"],
  "must_include": ["电池", "售后"],
  "must_not_include": ["继续使用"],
  "answerable": true,
  "citation_required": true,
  "notes": "安全类问题，必须给出断电停用提示"
}
```

组成：**12 条知识 + 5 条订单 + 4 条报告 + 4 条越权/安全 + 3 条提示注入 + 2 条负样本 = 30 条**。

**Step 2：指标模块** `eval/agent_metrics.py`

纯函数：

- `route_accuracy`：路由是否正确
- `capability_match`：是否真的调用了 RAG / 订单 / 报告能力
- `tool_selection_accuracy`：工具集合是否匹配
- `citation_coverage`：回答是否带来源
- `safety_pass_rate`：禁止内容是否出现、该拒答是否拒答
- `keyword_recall`：回答是否覆盖关键点
- `latency_p50/p95`：延迟分布

**Step 3：评测脚本** `eval/run_agent_eval.py`

```bash
python -m eval.run_agent_eval --dry-run
python -m eval.run_agent_eval --limit 5
python -m eval.run_agent_eval --category knowledge
python -m eval.run_agent_eval --output eval/agent_results.jsonl
```

输出：逐题 JSONL + `eval/agent_report.md` 汇总表。

**Step 4：跑基线**

先跑 5 条验证脚本，再跑全量 30 条；全量前估算模型调用次数和费用。

**Step 5：写优化待办**

`docs/SPRINT5/优化待办.md` 记录 P001-P015、基线数字和证据。

## 4. 面试 16 问自测表

| # | 问题 | 目标答案要点 |
| --- | --- | --- |
| 1 | 这是 Agent 还是工作流？ | 混合：高频强约束走确定性流水线，开放式问题用 ReAct |
| 2 | 怎么保证知识问题一定 RAG？ | 路由 + RAG-first 流水线 + 测试断言 |
| 3 | 报告为什么不让 Agent 自由发挥？ | 步骤固定、风险高；直接读记录再一次生成 |
| 4 | 订单为什么不用 LLM？ | 结构化状态由代码返回，模型只解释 |
| 5 | 路由错了怎么办？ | 混合意图回退 ReAct，记录误路由，用评测调规则 |
| 6 | 工具预算怎么定？ | 按复杂度给硬上限，重复调用走缓存，超限明确报错 |
| 7 | 召回率多少，怎么测？ | 30 条分层评测 + Recall@3 + MRR + 人工抽检 |
| 8 | 为什么纯向量会漏关键词？ | `battery-safety` 案例；BM25 补精确匹配 |
| 9 | 为什么用 RRF？ | 不同检索器分数不可比，RRF 只用排名，稳健 |
| 10 | 引用是模型写的还是代码保证的？ | 代码提取、校验、补全 |
| 11 | 文档更新或删除怎么办？ | doc_id + 版本 + 先删后写 + 重建 |
| 12 | 怎么防提示词注入？ | 文档不可信 + 分隔符 + 工具层权限 + 对抗测试 |
| 13 | 超时/重试/熔断怎么设计？ | 只对幂等读操作重试，有限次数 + 退避 + 熔断 |
| 14 | 一次请求多少 token/多少钱/P95？ | 埋点实测，给 P50/P95 和单次成本 |
| 15 | 100 人并发怎么办？ | Streamlit/Chroma 限制、限流、队列、迁移结论 |
| 16 | 这是 demo 还是生产？ | 明确边界和下一步 |

## 5. 风险与注意

- 评测集是自己标的，有偏；写清标注口径和人工抽检比例
- 同一批用例跑 2 次取均值，避免模型波动误判
- 每次优化前后用同一份评测集，禁止换题
- 全量评测有 API 成本，先跑 5 条再决定
- 重构期间保持 `main` 可运行，所有改动走 `sprint5/*` 分支
- Docker 在 Windows 11 家庭版可能需要 WSL2；装不上就降级为本地 venv + 录屏
- 不为了功能数量增加未评测的页面
