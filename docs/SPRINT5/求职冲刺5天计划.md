# 求职冲刺 5 天计划：学习 + 完善项目一体化

> 目标岗位：AI 应用 / Agent 工程师
> 每天投入：4~6 小时，按 6 小时排
> 原则：先交付，再修行为，最后加深度；不先堆功能。
> 核心闭环：学一个概念 → 在代码里找到它 → 改一处 → 用同一份评测验证 → 写一段面试话 → 提交。

## 2. 每天固定 6 小时闭环

| 时间 | 内容 |

3. 面试一句话

缺一样，当天不算完成。

### 8.2 新增项任务与验收

#### A. LLM-as-judge 评测

- 新增 `eval/judge.py`、`prompts/judge_prompt.txt`、`tests/test_eval_judge.py`。
- 三个维度：`faithfulness`（回答是否只基于检索证据）、`answer_relevance`、`context_precision`。
- judge 输出固定 JSON；用 `qwen-turbo` 控制成本；失败重试 1 次。
- 人工标注 20 条做校准，一致率 ≥ 80%；低于 80% 先改 rubric，不上线。
- 关键词指标与 judge 并存，不互相替代。
- CI：nightly 或手动触发 5 条冒烟；指标回退 > 5% 失败；无 Key 时用回放夹具。
- 验收：报告新增 judge 表；人工一致率有数字；人为改坏一处能被 CI 拦下。

#### B. 成本与延迟

- 语义缓存只对 `knowledge` 路由生效；key = 归一化 query + 用户作用域 + 索引版本。
- 订单、报告、越权请求 100% 绕过缓存；TTL 24h；命中率埋点。
- 模型分级：路由/改写用 `qwen-turbo`，生成用 `qwen-max`；配置化，不写死。
- 埋点：TTFT、总延迟、输入/输出 token、单次成本。
- 验收：知识 FAQ 集缓存命中率 ≥ 30%；订单/报告绕过测试 100%；跨用户隔离测试通过；P95 与单次成本有前后对比。

#### C. 多轮记忆

- 滚动摘要：超过 N 轮把旧消息压缩为摘要，保留最近 K 轮原文。
- 用户偏好长期记忆：只存偏好（如“家里有宠物”），不存订单/身份；提供清除入口。
- 新增 8 条多轮用例：指代消解、上下文切换、记忆召回。
- 验收：多轮指代准确率 ≥ 80%；10 轮对话 token 降 ≥ 30%；记忆清除测试通过。

#### D. 第 4 项（三选一，默认 Demo + 反馈闭环）

> 方向偏平台就把本节替换为 MCP 工具服务；偏企业工作流就替换为 HITL。任务可以换，验收标准保持可量化。

- 部署：Streamlit Community Cloud / Railway / 本地 Docker + 公网隧道，三选一；secrets 不入库；加基础限流。
- 前端增加 👍/👎（可选原因）；记录 query、answer、trace_id、route。
- 新增 `scripts/promote_badcase.py`：把差评转成 `eval/agent_cases.jsonl` 草稿。
- 验收：live URL 可访问；至少 10 条反馈记录；1 条 badcase 成功晋升为评测用例。

### 8.6 风险

- judge 成本与一致性：只抽样评，rubric 先人工校准。

- 记忆隐私：只存偏好，不存订单/身份，提供清除。
- 部署密钥：只放平台 secrets，不进仓库。
- 时间超支：优先保 Day 2/3 核心 + README 数字；D 项可降级为录屏 + 本地反馈。
