# 第 2 天：身份与权限边界

## 今天的目标

区分四个容易混淆的概念：

1. **认证**：你是谁，由谁证明。
2. **授权**：你能不能访问某条订单或使用记录。
3. **业务身份**：登录账号对应哪个家电客服用户。
4. **运行时上下文**：本次 Agent 请求可以使用的用户和月份。

之前的用户下拉框不是认证。它只是让浏览器提交一个 `user_id`，攻击者可以把它改成任意值。工具层虽然会再次校验资源归属，但比较对象本身已经被伪造。

## 当前实现

### OIDC 模式

项目检测到 `.streamlit/secrets.toml` 中存在 `[auth]` 后，会调用：

```python
st.login()
st.user.email
st.logout()
```

可信邮箱通过 `config/auth.yml` 映射到业务用户 ID。未绑定的邮箱会被拒绝，不会自动创建用户。

### 固定演示模式

没有 OIDC 配置时，应用只读取服务端环境变量：

```dotenv
DEMO_USER_ID=1001
```

页面没有用户切换控件。想换演示用户，必须修改服务端配置并重启应用。这是演示模式，不是生产认证。

## 为什么不能直接相信邮箱

即使 OIDC 已经验证邮箱，也不能让模型或浏览器自行决定它属于哪个 `user_id`。邮箱到业务用户的映射必须保存在服务端，并且需要审计和过期机制。

## 代码阅读顺序

1. `app.py` 中的 `_require_identity`：选择认证模式并阻断未登录请求。
2. `services/auth_service.py`：把可信身份解析成业务用户。
3. `config/auth.yml`：维护邮箱映射。
4. `agent/tools/agent_tools.py`：工具层再次执行资源归属校验。

这形成了两道防线：

- 身份层：不能随便选择或伪造用户。
- 工具层：即使模型被提示词注入，也不能读取其他用户的数据。

## 面试官可能追问

### 1. 为什么不用密码输入框做登录？

回答要点：共享密码不能证明具体用户身份，也没有签名 Cookie、过期和撤销机制。Streamlit OIDC 使用可信身份提供方，应用只接收验证后的声明。

### 2. 没有 OIDC 配置时为什么还能运行？

回答要点：这是明确受限的演示模式，只使用服务端固定用户，页面无法切换身份。生产环境会强制要求 OIDC。

### 3. 工具层已经校验用户，为什么还要认证？

回答要点：工具校验解决“当前身份是否有权访问资源”；认证解决“当前身份是否可信”。缺少认证时，工具校验比较的是一个可伪造的值。

### 4. 如果 OIDC 邮箱没有映射怎么办？

回答要点：拒绝访问并提示账号未绑定，不自动创建业务用户。自动绑定可能造成数据串号。
