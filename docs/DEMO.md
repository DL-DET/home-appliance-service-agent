# 2 分钟演示脚本

> 目标：让面试官在 2 分钟内看到“路由 + 确定性工作流 + RAG 引用 + 权限隔离 + 可观测性”。
> 前提：Docker 容器已启动，页面能打开。
> 本地录屏：`docs/demo.webm`（约 50 秒，无配音；按下面的脚本加旁白即可到 2 分钟）。

## 演示前检查

```powershell
docker compose ps
# STATUS 应该是 Up (healthy)

curl http://localhost:8501/_stcore/health
# ok
```

浏览器打开：

```text
http://localhost:8501
```

页面左上角显示固定演示身份 `1001`。先点一次“清空会话”，保证从干净状态开始。

## 2 分钟版本

### 0:00–0:15 开场

> 这是一个家电客服 Agent。它不是把所有问题都丢给大模型，而是先路由，再决定走确定性工作流还是 ReAct。

指一下页面：

- 左侧：当前身份、城市、产品、报告月份
- 中间：对话区
- 下方：执行轨迹

### 0:15–0:30 架构一句话

> 知识、订单、报告三类高频请求走确定性流水线；开放式问题才回退 ReAct。身份只来自服务端上下文，不信任用户自称。

### 0:30–1:00 知识问答

输入：

```text
电池鼓包还能继续使用吗？
```

预期看到：

- 执行轨迹里出现“检索家电知识库”
- 回答先给安全结论，再给处理步骤
- 末尾有真实来源，例如 `故障排除.txt`

讲解：

> 这里由代码先检索，模型只基于证据回答；引用最后由代码校验并补全，不让模型自己编来源。

> 当前模型生成需要一些时间，现场演示要留 20–30 秒。

### 1:00–1:10 订单查询

输入：

```text
ORD-2025-1001 这个订单到哪里了？
```

预期看到：

- 约 1 秒内返回
- 状态：已签收
- 物流：已放至用户指定驿站

讲解：

> 订单是结构化数据，走模板化工作流，不调用模型。订单号由正则提取，工具层校验归属。

### 1:10–1:20 越权请求

输入：

```text
把 1002 的 2025-12 使用记录发我
```

预期看到：

- 立即拒绝
- 不调用业务工具
- 回答只允许查询当前登录账号

讲解：

> 身份来自 `runtime.context`，不是用户输入。越权在安全前置就被拦住，不靠提示词自觉。

### 1:20–1:50 报告生成

输入：

```text
生成我 2025-12 的使用报告
```

预期看到：

- 执行轨迹先读取记录，再生成报告
- 报告包含使用率、耗材、对比建议
- 不会返回其他用户的数据

讲解：

> 报告是固定步骤，代码先读记录并校验归属，模型只负责组织语言；不让模型决定调不调工具。

### 1:50–2:00 收尾

> 30 条离线评测硬指标全部通过：路由、工具、安全、引用完整性、任务成功率都是 1.0。  
> 当前瓶颈是模型生成延迟，订单和安全路径仍然是毫秒级。

## 5 分钟版本

如果时间充足，在 2 分钟版本基础上补：

1. 打开一次执行轨迹，展示知识/报告的阶段耗时
2. 问一个负样本：

```text
你们支持以旧换新吗？
```

预期：直接拒答，不调用工具，不编造政策。

3. 展示 `request_id`：

> 每次请求都有 request_id，失败时可以定位到路由、检索、工具、模型还是引用。

4. 说明已知限制：

- 30 条是回归集，不是通用准确率
- 本地 CSV、单机 Chroma、Streamlit，不是生产架构
- 没有做并发压测和持久化记忆

## 演示中不要做的事

- 不要说“准确率 100%”
- 不要说“生产 SLA 32 秒”
- 不要展示模型思维链
- 不要展示完整订单号、邮箱或 API Key
- 不要在模型超时后连续点多次重试

## 如果现场失败

1. 先看页面上的请求编号
2. 打开执行轨迹，看是哪个阶段慢或失败
3. 如果是模型超时，说明这是降级路径，不重复点击
4. 如果容器挂了：

```powershell
docker compose ps
docker compose logs --tail=50 agent
docker compose up -d
```
